# Lessons Learned

| Date | Ce qui s'est passé | Règle |
|------|-------------------|-------|
| 2026-08-30 | Le workflow GitHub appelait `npm run test:ci`, mais ce script avait disparu de `package.json` alors que `npm test` passait localement | Avant un push de livraison, vérifier la commande exacte exécutée par `.github/workflows/ci.yml` et conserver un alias `test:ci` explicite si le workflow en dépend |
| 2026-08-30 | Le build Next.js a échoué au prerender de `opengraph-image` car un conteneur Satori comportait plusieurs nœuds enfants sans `display` explicite | Dans les images Open Graph basées sur `ImageResponse`, donner `display: flex`, `contents` ou `none` à tout conteneur ayant plusieurs enfants ; préférer deux `span` dans un flex vertical à un texte avec `<br />` |
| 2026-08-30 | Le site continuait à vendre des prestations alors que l'activité était désormais centrée exclusivement sur des produits personnels | Un changement de modèle d'activité doit retirer simultanément les offres, CTA, routes SEO, formulaires, back-office, crons, dépendances et données structurées ; archiver avant de décommissionner |
| 2026-03-28 | Les métriques (50+, 12 clients, 98%) étaient inventées — Pierre les a fait retirer | Ne jamais inventer de chiffres. Demander les vrais chiffres ou ne pas en mettre |
| 2026-03-28 | Le projet Supabase SAPAL est un projet client existant, pas pour OptiPro | Toujours demander avant de toucher à un projet Supabase existant |
| 2026-03-28 | Pierre ne fait pas de marketing — il se concentre sur l'admin, les outils, l'automatisation | Ne pas proposer de features marketing (SEO, réseaux sociaux, etc.) dans les audits |
| 2026-03-28 | Compte GitHub = plaurent2812-debug (pas pl2878dev) | Vérifier le bon compte avant de créer des PR |
| 2026-03-31 | API Pennylane V2 quotes : `expiry_date` → `deadline`, `line_items_attributes` → `invoice_lines` | Les noms de champs V2 diffèrent de V1 — toujours consulter la doc V2 (pennylane.readme.io) |
| 2026-03-31 | API Pennylane V2 : `unit_price_cents` (int centimes) → `raw_currency_unit_price` (string euros) | V2 attend le prix en euros sous forme de string, pas en centimes |
| 2026-03-31 | API Pennylane V2 : `FR_0` n'existe plus pour la TVA → utiliser `exempt` | Pour franchise en base (auto-entrepreneur), le taux TVA V2 est `exempt` |
| 2026-03-31 | API Pennylane V2 : le champ `unit` est obligatoire sur chaque ligne | Toujours inclure `unit: 'piece'` (ou autre) dans les invoice_lines |
| 2026-04-28 | GSAP + Next.js : éviter `self.document` (n'existe pas hors browser global), passer par `rootRef.current?.querySelector` dans le scope du `useGSAP` | Toujours scoper les querySelector via le ref racine, pas via globals |
| 2026-04-28 | gsap.matchMedia : `context.conditions` est typé `Record<string, boolean> \| undefined`, caster vers le type des clés déclarées et vérifier `!conditions` avant usage | Toujours guard nullish + cast explicite des conditions matchMedia |
| 2026-04-28 | Quand un Server Component a besoin d'animations GSAP (Hooks React), créer un wrapper Client Component recevant les données en props ; garder JSON-LD et metadata côté Server | Pattern : page.tsx Server (SEO/data) → Client.tsx (animations + UI) |
| 2026-05-05 | react-pdf : `fontStyle: 'italic'` crash si la variante italic de la font n'est pas enregistrée via `Font.register` (`Could not resolve font for X, fontStyle italic`) | N'utiliser `fontStyle: 'italic'` que si la variante italic est enregistrée. Sinon, simuler via couleur/lineHeight |
| 2026-05-05 | react-pdf côté client + image distante (`<Image src="https://...">`) : risque CSP/CORS/worker. Précharger le logo en data URL via fetch + FileReader plus robuste | Pour les assets PDF côté client, précharger en data URL avant `pdf().toBlob()` |
| 2026-05-05 | Next.js metadata `template: '%s \| OptiPro'` du layout + `title: 'X \| OptiPro'` dans la page → résultat `X \| OptiPro \| OptiPro` (3+ occurrences) | Quand un template est défini dans le layout, ne JAMAIS répéter le suffixe dans les `title` des pages. Utiliser `title: { absolute: '...' }` pour bypass le template |
| 2026-05-05 | Remplacer `&apos;` par `'` dans des strings JS entre `'...'` casse le parsing TypeScript | Pour les strings JS contenant des apostrophes : utiliser `"..."` (double quotes) plutôt que `'...'`, ou échapper avec `\\'`. Ne jamais utiliser `&apos;` dans le JSON-LD (Google reçoit l'entité littéralement) |
| 2026-05-05 | Quand on supprime un fichier de `src/app/`, le cache `.next/dev/types/validator.ts` continue de référencer l'ancien fichier → erreur tsc | Après suppression d'une page : `rm -rf .next` puis re-run tsc pour purger le cache des types générés |
| 2026-05-05 | Pour forcer un redirect 301/308 depuis le domaine non-www vers www sur Vercel, utiliser `redirects()` avec `has: [{ type: 'host', value: 'opti-pro.fr' }]` dans `next.config.ts` | Vercel intercepte au niveau edge avant Next, et applique le `permanent: true` (308) au lieu du 307 par défaut |
| 2026-07-26 | Le repositionnement de juin n'avait touché que 4 pages : /contact, les 10 pages /services/*, les CGV, llms.txt, le manifest PWA et l'image OpenGraph vendaient encore l'offre admin 650-1950€/mois | Un changement de positionnement est un chantier **transverse** : faire un `grep -rn` des anciens prix/accroches sur `src/` ET `public/` avant de considérer la refonte terminée. Ne pas oublier les surfaces invisibles en navigation : manifest.ts, opengraph-image.tsx, llms.txt, JSON-LD du layout |
| 2026-07-26 | Un crawl du sitemap ne détecte pas les pages obsolètes déjà couvertes par un redirect 301 : /methode et /pourquoi-ce-prix répondaient 308 mais leur code (100% ancienne offre) vivait encore dans `src/app/` | Après dépublication d'une route, supprimer aussi le code source — sinon il réapparaît au prochain audit du code et fausse les greps. Vérifier `ls src/app/(public)/` et pas seulement le sitemap |
| 2026-07-26 | Les pages métier (/services/plombier etc.) étaient orphelines : présentes au sitemap, aucun lien interne ne les pointait (le footer ne listait que les villes) | Après création de pages SEO, vérifier le maillage réel : `curl` chaque page et grep les `href` — une page au sitemap sans lien entrant est mal crawlée |
| 2026-07-26 | Les pages métier contenaient des stats sourcées CAPEB/INSEE (« 6 à 8h par semaine », « 42€/h ») invérifiables, et le blog des « 30 artisans accompagnés » / « 9 artisans sur 10 » | Prolonge la leçon du 2026-03-28 : supprimer les stats non vérifiables même quand elles *citent* une source. Une source nommée ne rend pas le chiffre vrai |
| 2026-07-26 | Vérification menée sur les stats du blog : l'« étude CAPEB 2023 : devis sous 24h = 80% de signature » **n'existe pas** (chiffre recopié de blog en blog), et les attributions à l'INSEE (42€/h plombier, 60-90 j de délai) étaient fabriquées. Même la citation CAPEB conservée était inexacte : la source dit « 42% des artisans estiment que l'admin représente 25 à 75% de leur charge », pas « 10 à 25% du temps » | Avant de citer une stat : **ouvrir la source et y lire la phrase exacte**. Un curl en 403 ne prouve rien (anti-bot) — vérifier dans le navigateur. Et vérifier que le chiffre cité est bien celui de la source, pas une reformulation qui a dérivé |
| 2026-07-26 | Tentative de suppression d'articles dans blog.ts via un parseur d'accolades : le HTML du champ `contenu` contient des accolades → 11 objets détectés au lieu de 14, fichier corrompu | Ne jamais parser du JS/TS contenant du HTML par comptage d'accolades. Sauvegarder avant (`cp` en /tmp), et découper sur des marqueurs de ligne fiables (`  {` / `  },` à indentation fixe) en vérifiant le compte attendu par une assertion |
| 2026-07-27 | J'ai annoncé « le blog est invisible en production » sur la base d'opacités à 0 lues via `getComputedStyle` dans le navigateur automatisé. C'était un artefact : volet masqué = `requestAnimationFrame` gelé = GSAP figé sur son état de départ. Lighthouse rendait la page normalement (score 95, LCP 2,9 s — impossible si rien n'était peint) | Dans le navigateur automatisé, ne JAMAIS conclure à un bug d'animation à partir de `getComputedStyle` seul : le ticker peut être gelé. Recouper avec une capture d'écran (qui force le rendu), avec Lighthouse (un LCP prouve qu'un élément a été peint) et avec le HTML serveur. Deux mesures identiques à 3 s d'intervalle = ticker gelé, pas animation cassée |
| 2026-07-27 | En vérifiant ce faux positif, un vrai défaut est apparu : `gsap.from(\`.${styles.x}\`)` sur sélecteur string met l'élément à opacity 0 et le laisse ainsi si le tween ne joue jamais (élément sous la ligne ScrollTrigger « top 88% » mais déjà à l'écran). Le pattern qui marche (HomePageClient) fait `gsap.set` + `gsap.to` sur des éléments résolus via `rootRef.current?.querySelectorAll` | Pour toute animation de révélation : cibler via le ref racine, utiliser `set`+`to` plutôt que `from`, ne jamais mettre `opacity: 0` en CSS (l'état visible est la source de vérité), et révéler immédiatement tout élément déjà intersecté au setup. Helper dédié : `src/lib/gsap-reveal.ts` |
| 2026-07-27 | Aucun déploiement Vercel depuis le 10 juin alors que 4 commits avaient été poussés sur `main` — le déploiement échouait silencieusement (`vercel --prod` a révélé l'erreur, l'UI Vercel ne montrait juste plus rien de récent). Cause : `vercel.json` déclarait un cron horaire (`0 * * * *`), incompatible avec le plan Hobby (1 cron/jour max) — Vercel rejette **tout le déploiement**, pas juste ce cron | Si un push sur `main` ne produit pas de nouveau déploiement en Production, vérifier `vercel ls` (âge du dernier déploiement) et retenter un `vercel --prod` en direct pour voir l'erreur réelle — l'UI n'alerte pas toujours de façon visible. Sur Hobby, tout cron plus fréquent que quotidien casse le déploiement entier |
| 2026-07-27 | Résiliation d'un abonnement tiers (Pennylane) avec une intégration profonde (19 fichiers : cron, sync manuelle, badges admin) | Ne pas supprimer le code par réflexe. Traiter en 2 temps : 1) ce qui bloque activement (le cron qui empêchait le déploiement) 2) le reste, à trancher explicitement avec l'utilisateur plus tard — poser la question plutôt que présumer l'ampleur du nettoyage voulu |
| 2026-07-27 | Retrait complet de Pennylane (suite de la leçon ci-dessus, décision prise) : `validateFactureAction`/`markFactureAsPaidAction` dépendaient de l'API Pennylane pour passer une facture en "envoyée"/"payée", et la fiche facture affichait explicitement "conformité Factur-X gérée par Pennylane" | Avant de retirer une intégration tierce, tracer ce qui en dépend fonctionnellement (pas que les imports) : ici la validation de facture et la conformité légale Factur-X seraient devenues des no-op silencieux sans remplacement. Demander comment le flux métier continue (ici : facturation externe) avant de coder |
| 2026-07-27 | La route `/api/cron/sync-pennylane` n'avait plus de cron déclencheur (retiré de vercel.json) mais restait appelable par URL directe sans authentification effective (`CRON_SECRET` non configuré en prod), avec accès service_role Supabase | Retirer un cron de `vercel.json` ne suffit pas : la route reste exposée. Supprimer aussi le code de la route, ou vérifier qu'un secret est bien configuré en prod si elle doit rester |
| 2026-07-27 | Les 4 pages métier (`plombier`, `electricien`, etc.) dupliquent chaque FAQ answer entre un bloc `faqJsonLd` en haut de fichier et les props `faq[]` visibles plus bas — un remplacement en masse (`sed`) sur le seul texte visible aurait fait diverger le JSON-LD envoyé à Google du contenu affiché | Avant tout remplacement mécanique en masse (sed/grep) sur des pages avec JSON-LD inline, vérifier s'il y a une duplication manuelle JSON-LD/props — sinon compter les occurrences attendues par fichier avant ET après pour détecter une divergence |
